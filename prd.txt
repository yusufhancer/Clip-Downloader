# Product Requirements Document

## YouTube Clip Downloader

### 1. Product Overview

YouTube Clip Downloader adalah web satu halaman yang memungkinkan user mengambil dan mengunduh hanya bagian tertentu dari sebuah video YouTube berdasarkan waktu mulai dan waktu akhir.

Contoh penggunaan:

Video YouTube memiliki durasi 30 menit.

User hanya ingin bagian:

* Start: `25:00`
* End: `26:10`

Sistem hanya akan memproses bagian tersebut dan menghasilkan file video berdurasi 1 menit 10 detik.

Produk harus fokus pada kecepatan, kesederhanaan, dan kemudahan penggunaan.

Tidak ada dashboard, halaman akun, menu kompleks, atau fitur sosial.

Semua fungsi utama berada dalam satu halaman.

---

# 2. Product Goal

Tujuan utama produk:

* Mempermudah user mengambil bagian tertentu dari video tanpa perlu mengunduh seluruh video.
* Mengurangi waktu download dan ukuran file.
* Memberikan pengalaman yang cepat dan sederhana.
* User harus bisa mendapatkan clip hanya dalam beberapa langkah.
* Interface harus mudah dipahami bahkan oleh pengguna baru.

---

# 3. Target User

Target utama:

* Content creator
* Video editor
* Pelajar
* Pengguna yang ingin menyimpan potongan tertentu dari video
* Pengguna yang ingin mengambil reference clip
* Pengguna yang membutuhkan potongan singkat dari video panjang

# 4. Core User Flow

Flow utama:

```text
User membuka website
↓
User paste URL YouTube
↓
User menekan tombol Load Video
↓
Backend memvalidasi URL
↓
Sistem mengambil metadata video
↓
Video preview ditampilkan
↓
User menentukan Start Time
↓
User menentukan End Time
↓
User memilih format dan kualitas
↓
User menekan Download Clip
↓
Server memproses video
↓
Progress processing ditampilkan
↓
Clip selesai
↓
User mengunduh file
```

Target utama:

User dapat mencapai proses download dengan sesedikit mungkin interaksi.

# 8. URL Validation

Sebelum request dikirim ke backend:

Error yang perlu ditangani:


```text

```

```text
Video unavailable
```

```text
Private video
```

```text
Video cannot be processed
```

```text
Unsupported URL
```

Error ditampilkan langsung di bawah input.

Tidak menggunakan browser alert.

# 15. Time Validation

Rules:

```text
Start Time >= 0
```

```text
End Time <= video duration
```

```text
Start Time < End Time
```

Clip tidak boleh memiliki durasi `0`.

Jika input salah:

```text
End time must be greater than start time.
```

atau:

```text
Selected time exceeds the video duration.
```

---

# 16. Selected Clip Duration

Tampilkan durasi clip secara realtime.

Contoh:

```text

01:10
```

```text
clipDuration = endTime - startTime
```

# 21. Backend Processing Flow

Ketika user menekan Download Clip:

Frontend mengirim request seperti:

```json
{
  "videoId": "example",
  "startTime": 1500,
  "endTime": 1570,
  "format": "mp4",
  "quality": "720p"
}
```

Timestamp dikirim dalam satuan detik.

Backend melakukan:

```text
Validate request
↓
Validate video
↓
Validate timestamp
↓
Retrieve source media
↓
Extract selected range
↓
Encode/remux if required
↓
Generate output file
↓
Return download result
```

---

# 22. Processing Job

Processing video sebaiknya menggunakan sistem job.

Status:

```text
queued
processing
completed
failed
expired
```

Setiap request mendapat:

```text
jobId
```

Contoh:

```json
{
  "jobId": "uuid",
  "status": "processing"
}
```

Frontend menggunakan jobId untuk mengecek status.

# 30. Privacy

* Data personal yang tidak diperlukan

IP address tidak perlu disimpan kecuali memang dibutuhkan untuk security/rate limiting dan harus ditangani sesuai kebijakan privasi.

---

# 31. Security

Backend wajib melakukan:

* URL validation
* Parameter validation
* Request size limitation
* Rate limiting
* Input sanitization
* Output filename sanitization

Backend tidak boleh menerima arbitrary URL.

Hanya domain/source yang memang didukung.

Tujuan penting:

Mencegah SSRF.

Jangan izinkan user memasukkan URL internal seperti:

```text
localhost
127.0.0.1
192.168.x.x
internal network
```

Backend juga harus mencegah command injection saat menjalankan media-processing tools.

Semua argument harus diberikan sebagai structured arguments, bukan concatenated shell command.

---

# 32. Rate Limiting

Karena video processing membutuhkan resource tinggi, rate limiting wajib tersedia.

Rate limit dibuat configurable.

Contoh:

```text

MAX_CONCURRENT_JOBS
MAX_CLIP_DURATION
MAX_VIDEO_DURATION
```

Jangan hard-code business limit ke banyak tempat.

# 40. Media Processing

Media clipping sebaiknya dilakukan menggunakan tool media seperti:

```text
FFmpeg
```

FFmpeg bertanggung jawab untuk:

* trimming
* remuxing
* audio extraction
* encoding jika diperlukan

Jika memungkinkan gunakan stream copy untuk mengurangi processing.

Encoding ulang hanya dilakukan ketika diperlukan.

---

# 41. Job Queue

Untuk production:

Jangan melakukan proses video berat langsung dalam HTTP request utama.

Gunakan:

```text
API
↓
Queue
↓
Worker
```

Benefit:

* Request tidak timeout
* Bisa mengatur concurrency
* Bisa retry job
* Server lebih stabil

---

# 42. Caching

Metadata video dapat di-cache berdasarkan:

```text
videoId
```

Contoh TTL:

```text
15–60 minutes
```

Tujuannya mengurangi request metadata berulang.

Output clip tidak perlu cache jangka panjang.
